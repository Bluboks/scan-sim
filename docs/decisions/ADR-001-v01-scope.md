# ADR-001: v0.1 범위와 실물 비교 없는 현실성 기준

- 상태: ACCEPTED
- 날짜: 2026-10-02
- 결정 주체: 소유자 (범위, 비교 쌍 없음, 현실성 판단 위임)

## 배경

[최초 명세](../archive/2026-10-02-initial-brief.md)는 v0.1과 v0.2 범위를 나눠 두었다.
명세의 최종 목표는 `office-medium`이 실제 사무용 복합기 300 dpi 스캔본과 육안상
비슷해지는 것이다. 그런데 원본과 실제 스캔본으로 된 비교 쌍이 없다.

## 결정

- 소유자 결정: v0.1만 먼저 구현한다. 비교 쌍은 없다. 현실성은 에이전트가 적절히
  판단한다.
- v0.1에 포함: PNG/JPG(및 TIFF/BMP) 입력, JPG/PNG 출력, 명세 §38의 단계 전부, 프리셋
  5개, seed, 일괄 처리, 변형, JSON 메타데이터.
- `office-adf`, `ocr-stress` 프리셋이 명세상 필요로 하는 세로줄과 가로 띠는 v0.1에
  넣는다. 별도 ADF skew 항목은 넣지 않고 `office-adf`의 넓은 회전 범위로 대신한다.
- v0.2로 미룸: PDF 입출력, 먼지 점, 파라미터 스윕, `--preset-family`, 실물 캘리브레이션.
  (2026-10-03: PDF 입력은 소유자 요청으로 앞당겼다. [ADR-005](ADR-005-pdf-input.md))
- 현실성 기준(에이전트 결정(위임)): 일반 사무용 복합기 컬러 300 dpi JPEG 스캔에서
  흔히 보이는 값으로 맞춘다. 흰 배경은 245~253 수준이고 미세한 질감이 있다. 단색
  검정은 20~45, 10 pt 획 중심은 20~40 정도다. 1 px 표 선은 회색으로 남는다. 판단
  근거와 측정값은 [VALIDATION](../ops/VALIDATION.md)에 쓴다.

## 이유·trade-off

명세의 v0.1/v0.2 경계를 그대로 따르면 범위 논쟁이 없다. TIFF/BMP 입력은 Pillow가 이미
읽으므로 추가 비용이 없어 포함했다. 비교 쌍이 없으므로 현재 프리셋 값은 실측이 아니라
추정이다. 특정 기기와 비교하면 차이가 날 수 있다.

## 후속

v0.2에서 실물 캘리브레이션(명세 §35~36)을 넣으면 기기별 프리셋으로 이 추정치를 대체한다.
